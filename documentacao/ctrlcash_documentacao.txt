1. INTRODUCAO
================================================================================

CashCtrl e um aplicativo movel desenvolvido em Flutter com backend Firebase,
projetado para auxiliar microempreendedores e pequenos negocios no controle
financeiro e na gestao de custos de produtos.

Seu diferencial e o Calculador de Ficha Tecnica (Ticket do Produto), que permite
ao usuario cadastrar produtos de compra (insumos), montar fichas tecnicas
(receitas) e calcular automaticamente se cada produto gera lucro ou prejuizo,
apresentando o custo detalhado por item e a participacao percentual de cada um.

O app tambem oferece comparativo de ofertas entre fornecedores por produto,
com escolha manual da oferta ativa que alimenta o calculo, historico de
auditoria de precos (append-only) e exportacao de relatorios para Excel.

5. DESCRICAO DA IMPLEMENTACAO
================================================================================

5.1 MODELOS (lib/models/)
  - AppUser: Perfil do usuario (nome, email, empresa, CNPJ, segmento,
             telefone, endereco, preferencias de notificacao)
  - AppTransaction: Transacao (tipo receita/despesa, categoria, descricao,

  - Ingredient: Produto comprado (nome, unidade, preco de compra, quantidade

5.3 PROVIDERS (lib/providers/)

6. DIAGRAMA ENTIDADE-RELACIONAMENTO
================================================================================

O banco de dados Firestore utiliza uma estrutura hierarquica com isolamento
por usuario (cada usuario so acessa os proprios dados):

  users (colecao principal)
    |
    |-- {uid} (documento do usuario)
          |
          |-- transactions (subcolecao)
          |     |-- {txId}
          |
          |-- budgets (subcolecao)
          |     |-- {budgetId}
          |
          |-- ingredients (subcolecao)
          |     |-- {ingredientId}   (contem offers[] embutido + activeOfferId)
          |
          |-- products (subcolecao)
          |     |-- {productId}
          |
          |-- price_audit_logs (subcolecao)
                |-- {logId}

Relacoes:
  - products.recipe[].ingredientId -> ingredients.id (referencia ao produto)
  - ingredients.activeOfferId -> ingredients.offers[].id (oferta que alimenta o custo)


7. ESQUEMA DO BANCO DE DADOS
================================================================================

7.1 users/{uid}
  - nome: String
  - email: String
  - empresa: String (opcional)
  - cnpj: String (opcional)
  - segmento: String (opcional)
  - telefone: String (opcional)
  - endereco: String (opcional)

7.2 users/{uid}/transactions/{txId}
  - type: "receita" | "despesa"
  - category: String (ex: "Insumos", "Vendas")
  - description: String
  - amount: Number (double, deve ser > 0 - RN01)
  - date: String (ISO 8601)
  - paymentMethod: "dinheiro"|"credito"|"debito"|"pix"|"transferencia"|"outro"
  - recurring: Boolean
  - budgetId: String (opcional, referencia ao orcamento)

7.3 users/{uid}/budgets/{budgetId}
  - category: String
  - limit: Number (double)
  - monthly: Boolean
  - createdAt: String (ISO 8601)

7.4 users/{uid}/ingredients/{ingredientId}
  - name: String
  - unit: "g"|"kg"|"L"|"ml"|"un"|"pct"
  - purchasePrice: Number (double, >= 0)
  - packageQuantity: Number (double)
  - offers: Array<{supplier, productName, price, quantity}> (max 15)
  - activeOfferId: String (opcional)
  - createdAt: String (ISO 8601)
  Preco por unidade = activeOffer ? preco/qtd da oferta : purchasePrice/packageQuantity

7.5 users/{uid}/products/{productId}
  - name: String
  - description: String
  - recipe: Array<{ingredientId, ingredientName, quantity}>
  - laborCost: Number (mao de obra, double)
  - packagingCost: Number (embalagem, double)
  - salePrice: Number (double)
  - createdAt: String (ISO 8601)

7.6 users/{uid}/price_audit_logs/{logId}
  - action, entityType, entityId, summary
  - preco antes/depois, timestamp (serverTimestamp), expireAt (+180 dias)
  - append-only: sem update nem delete (regra)


8. INSTALACAO DO CASHCTRL
================================================================================

1. Clonar o repositorio:
   git clone https://github.com/JoaoVikthor/ctrlcash.git
   cd ctrlcash

2. Configurar variaveis de ambiente:
   Copie o arquivo .env.example para .env e preencha com suas chaves Firebase:
   - FIREBASE_PROJECT_ID
   - FIREBASE_ANDROID_API_KEY / FIREBASE_ANDROID_APP_ID
   - FIREBASE_WEB_API_KEY / FIREBASE_WEB_APP_ID / FIREBASE_WEB_MEASUREMENT_ID
   - FIREBASE_AUTH_DOMAIN / FIREBASE_STORAGE_BUCKET / FIREBASE_MESSAGING_SENDER_ID

3. Configurar Firebase:
   - Criar projeto no Firebase Console (ou usar existente)
   - Ativar Authentication (Email/Senha)
   - Criar Firestore Database e aplicar firestore.rules
   - Colocar android/app/google-services.json (baixado do Console)

4. Instalar dependencias e executar:
   flutter pub get
   flutter run

   Para web:
   flutter run -d chrome

================================================================================

9.1 Login e Cadastro

  - Passo 1: Dados pessoais (nome, email, senha, confirmacao, termos)
  - Passo 2: Dados do negocio (empresa, segmento, telefone, endereco, CNPJ opcional)

9.2 Dashboard

9.3 Transacoes
  - Acesse via menu lateral > Transacoes
  - Barra de resumo (receitas, despesas, saldo)
  - Busca por descricao ou categoria
  - Filtros por tipo (Todas, Receitas, Despesas) e por categoria
  - Deslize para esquerda para excluir
  - Toque no "+" para criar nova transacao (tipo, valor, descricao, categoria,

9.4 Orcamentos
  - Acesse via menu lateral > Orcamentos
  - Defina limites de gasto mensal por categoria

9.5 Relatorios
  - Acesse via menu lateral > Relatorios
  - 4 indicadores: Lucro Liquido, Margem, Receita Total, Custos Totais
  - Grafico receitas vs custos (6 meses), custos por categoria, top 5
  - Botao "Exportar Excel" gera .xlsx (Resumo, Mensal, Transacoes);

9.6 Produtos (Parque de Insumos)
  - Acesse via menu lateral > Produtos

    embalagem; o app calcula preco por unidade automaticamente
  - Durante a criacao, registre ofertas de fornecedores (ate 15)

  - Escolha a oferta ativa (a mais barata esta marcada "melhor"); o custo da

9.7 Ficha Tecnica de Produtos

9.10 Auditoria de Preços

9.11 Perfil, Notificações e Segurança

11. MANUAL DO ESTUDANTE
================================================================================

11.1 Calculo de Lucro/Prejuizo (ProductCalculator)
  - custoTotal = Total Insumos + Mao de Obra + Embalagem
  - Lucro = Preco Venda - custoTotal
  - Margem % = (Lucro / Preco Venda) x 100
  - Markup = Preco Venda / custoTotal
  - Lucro >= 0 -> DÁ LUCRO (verde); Lucro < 0 -> DÁ PREJUÍZO (vermelho)

11.2 Participacao percentual
  - Cada item da receita exibe sua fatia no custo total (qtd x preco/unidade)

11.3 Comparativo de Ofertas
  - Para cada produto, ofertas de varios fornecedores (preco, quantidade)
  - App ranqueia por preco por unidade e destaca a melhor
  - A oferta ativa (escolhida manualmente) alimenta o custo da ficha tecnica
  - Cartao informativo mostra a economia possivel ao trocar de fornecedor


12. CONSIDERACOES FINAIS
================================================================================

12.1 Arquitetura
  - Arquitetura em camadas: Models -> Services -> Providers -> Screens
  - Gerenciamento de estado via Provider com streams Firestore em tempo real
  - Calculadora de ficha tecnica como classe utilitaria pura (testavel)

12.2 Regras de Negocio
  - RN01: Valores de transacao devem ser maiores que zero
  - RN02: Isolamento total por UID no Firestore
  - RN03: Preco por unidade = preco da embalagem / quantidade da embalagem
          (ou da oferta ativa, quando houver)
  - RN04: Lucro/Prejuizo = preco venda - (insumos + mao de obra + embalagem)

12.3 Sistema de Cores
  - Fundo:            #0D1E16 (verde-escuro/preto)
  - Verde Principal:  #165A41 (botoes, estados ativos)
  - Dourado:          #B89775 (destaques, icones)
  - Cartoes:          #142A20 (fundo de cards)
  - Texto Secundario: #7A8B83 (legendas)
  - Erro: Vermelho | Sucesso: Verde

12.4 Seguranca
  - Chaves Firebase nunca sao hardcoded (carregadas de .env)
  - .env, google-services.json, keystores e local.properties fora do git
  - Regras Firestore bloqueiam acesso nao autorizado (isolamento por UID)
  - price_audit_logs: somente leitura e criacao (imutavel)
